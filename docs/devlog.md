# Дневник разработки — новости как блог

Раз в две недели на странице «Новости» выходит заметка «Дневник разработки»: что изменилось
в играх студии за это время. Это обычная новость сайта (README, «Новости»), только с черновиком,
который готовит агент, и с одобрением владельца (поручение 06). О чём пишем и чего не пишем —
устав, `docs/10-channels.md`; голос — `docs/09-voice.md`.

## Порядок

1. **Раз в две недели, в понедельник,** регламентная задача «Дневник разработки» (роль «PR и
   сообщество», задание — `routines/devlog.md` в `Nefeste/uprava`) клонирует игры и запускает

   ```bash
   python3 tools/devlog.py --games <папка с клонами игр>
   ```

   Скрипт пишет `news/<дата>-devlog.ru.md` с полем `review: draft` — заготовку из `STATUS.md`
   каждой игры: версия, этап, что дальше. Если прошлый дневник моложе 13 дней, скрипт ничего
   не делает.
2. **Агент переписывает заготовку** голосом студии по шаблону ниже и открывает PR из ветки
   `claude/devlog-<дата>`. `STATUS.md` написан для команды: номера PR, ADR, теги, `versionCode`
   и «ворота» игроку ничего не говорят — их в новости нет.
3. **Владелец правит и одобряет:** ставит `review: checked` (или убирает поле) и сливает PR —
   это и есть публикация. Новость с `review: draft` сайт не показывает: ни на странице, ни
   в ленте, ни на главной; `tools/check.py` напоминает о ней.
4. **Позже** «Сени» (фаза 2) повторяют вышедшую новость в Telegram и ВКонтакте — тоже после
   одобрения владельца на Пульте.

## Шаблон

```markdown
---
date: 2026-10-19
title: Дневник разработки: 19 октября
review: draft
---
Первый абзац — главное за две недели одной-двумя фразами. Он же идёт на главную и в ленту.

- «Вотчина». Что изменилось для игрока и в какой версии; где это увидеть.
- «Длинные нарды». …
- «Анамнез». …
- «Сказы». …
- «Узоры». …

Последний абзац — что дальше, без сроков, которых нет в дорожных картах, и вопрос
к читателям, если он есть. Ссылки — на страницы игр: [«Вотчина»](https://gornitsa.games/votchina/).
```

## Правила

- Только то, что игрок может увидеть или проверить: новая возможность, исправление, закрытый тест,
  выход в RuStore. Без внутренних слов: «PR», «ADR», «тег», «CI», «ворота», «этап Ж».
- Числа — только с источником (`STATUS.md`, раздел версии в README игры), дат выхода — только тех,
  что записаны в дорожной карте игры. Не пишем «лучший», «первый», «№1».
- Игра без изменений за две недели — строку можно не писать.
- «Анамнез» — игра, а не медицинский справочник: без медицинских советов и обещаний «научит лечить».
- Без имён, ников и цитат игроков; находки тестировщиков — обезличенно: «тестировщик заметил…».
- Формат новости — README, «Новости»: абзацы и списки, без заголовков, HTML и картинок;
  заголовок — до 90 знаков.

# gornitsa.games

Сайт студии мобильных игр «Горница» на русском и английском: главная, страницы «Вотчины», поддержка, политика конфиденциальности и страница 404. Сайт статический: HTML, CSS и немного JavaScript, без сборщиков и зависимостей. Шрифты (Kurale и Onest, лицензия SIL OFL) раздаются с того же сервера, поэтому сайт не обращается к Google и другим внешним сервисам. В репозитории шрифтов и готовых страниц нет: их скачивает `deploy/fetch-fonts.sh` и собирает `build.py`.

## Структура

```
src/                  шаблоны страниц (редактировать тексты здесь)
  index.html
  about.html          «О студии»: миссия, ценности, обещания игрокам (пересказ устава студии)
  brand.html          брендбук: знак, цвета, шрифты, орнамент — вживую из стилей сайта
  support.html
  privacy.html        единая политика конфиденциальности (у каждой вышедшей игры — свой раздел)
  404.html
  votchina/           страницы «Вотчины»: об игре, турниры, удаление профиля
                      (privacy.html — переадресация на общую политику, раздел «Вотчина»)
  en/                 английская версия тех же страниц
  partials.py         общая шапка, подвал и <head> на обоих языках
  brandmark.svg       знак «Горницы» для шапки
site/                 сайт, который выкладывается на сервер (страницы *.html собирает build.py)
  assets/brand.css    токены бренда: копия brand/tokens.css из Nefeste/gornitsa, здесь не правится
  assets/site.css     стили
  assets/site.js      узор-раскраска на главной, орнамент, кнопка «Скопировать»
  assets/games/       баннеры, значки и снимки экрана игр (WebP)
  assets/fonts/       шрифты woff2 (скачивает deploy/fetch-fonts.sh)
  favicon.svg, robots.txt, sitemap.xml
build.py              собирает site/*.html из src/
deploy/
  setup-server.sh     первичная настройка VPS: nginx, HTTPS, файрвол
  deploy.sh           выкладка сайта со своего компьютера
  fetch-fonts.sh      скачивает шрифты в site/assets/fonts
  bootstrap.sh        настройка сервера одной командой и автообновление из GitHub
  update-site.sh      автообновление (запускается таймером раз в 5 минут)
  nginx/gornitsa.games.conf
  votchina/           сервер игры «Вотчина» на этой же машине (см. ниже)
    setup.sh          настройка: Node, служба, ключи, таймеры
    pull.sh           сборка из ветки vps и выгрузка базы (каждые 2 минуты)
    nginx.sh          сайт votchina.gornitsa.games в nginx и его сертификат
    backup.sh         копия базы раз в сутки
  nardy/              сервер игры «Длинные нарды» на этой же машине (см. ниже)
    setup.sh          настройка: Bun, служба, ключ, таймеры
    pull.sh           сборка из ветки vps (каждые 2 минуты)
    nginx.sh          nardy.gornitsa.games в nginx (с WebSocket) и его сертификат
    backup.sh         копия базы раз в сутки
```

## Как посмотреть локально

```bash
bash deploy/fetch-fonts.sh
python3 build.py
python3 -m http.server 8000 -d site
# открыть http://localhost:8000
```

## Как поменять текст

1. Отредактируйте нужную страницу в `src/` (шапку и подвал — в `src/partials.py`).
2. Запустите `python3 build.py`.
3. Сделайте `git push` — через несколько минут сервер обновит сайт сам.

Стили и скрипты редактируются прямо в `site/assets/`, кроме `brand.css`: это копия
`brand/tokens.css` из устава студии [`Nefeste/gornitsa`](https://github.com/Nefeste/gornitsa)
с пометкой источника в первой строке. Цвета, шрифты и скругления меняются сначала там, потом
копия переносится сюда.

Страницы «О студии» и «Брендбук» пересказывают устав студии (`docs/01-mission.md`,
`docs/02-values.md`, `brand/README.md`). Меняется обещание или правило бренда — сначала
в уставе, потом здесь, в том же заходе.

У каждой страницы есть пара на другом языке: русская `src/support.html` и английская `src/en/support.html`. Правьте обе, а новую страницу добавьте в список `pages` в `build.py` — тогда в шапке появится переключатель языка, а в `<head>` — ссылки `hreflang`. Надписи, которые рисует скрипт (подсказки на пяльцах, кнопка «Скопировать»), — в начале `site/assets/site.js`.

## Запуск с нуля

### 1. Домен

Домен gornitsa.games регистрируется на Рег.ру. После оплаты DNS-серверы по умолчанию — ns1.reg.ru и ns2.reg.ru, их менять не нужно.

### 2. VPS

Сервер заказан в Рег.облаке (тот же аккаунт, что и домен). Подойдёт и любой другой российский провайдер:

- ОС: Ubuntu 24.04 или 26.04;
- 1 vCPU, 1–2 ГБ RAM, 10+ ГБ диска — для статического сайта этого более чем достаточно;
- локация: Москва или Санкт-Петербург;
- при создании добавьте свой публичный SSH-ключ (`~/.ssh/id_ed25519.pub`). Если ключа нет: `ssh-keygen -t ed25519`.

### 3. DNS

В личном кабинете Рег.ру: «Домены» → gornitsa.games → «DNS-серверы и управление зоной» → добавьте две записи:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | @ | IP вашего VPS |
| A | www | IP вашего VPS |

Записи обычно начинают работать через 15 минут — несколько часов. Проверка: `dig +short gornitsa.games`.

### 4. Публикация исходников на GitHub

Сервер забирает сайт из репозитория, поэтому сначала отправьте код на GitHub. Репозиторий должен быть публичным (в нём нет паролей и ключей, только сайт):

```bash
git remote add origin https://github.com/Nefeste/gornitsagames.git
git push -u origin main
```

### 5. Настройка сервера одной командой

Войдите на сервер (`ssh root@IP_СЕРВЕРА` или через консоль в панели провайдера) и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Nefeste/gornitsagames/main/deploy/bootstrap.sh | bash
```

Скрипт скачает репозиторий в `/opt/gornitsa`, поставит nginx, закроет лишние порты, выложит сайт и включит автообновление. Как только DNS начнёт указывать на сервер, он сам выпустит бесплатный сертификат Let's Encrypt и включит HTTPS.

### 6. Обновления сайта

Просто делайте `git push` в ветку `main`: сервер проверяет GitHub каждые 5 минут и выкладывает новую версию сам. Журнал: `journalctl -u gornitsa-update -n 50`. Скрипт автообновления тоже берётся из репозитория (`deploy/update-site.sh`), а при изменении `deploy/votchina/` он доводит настройку сервера «Вотчины».

Если репозиторий нужен закрытым, сайт можно выкладывать со своего компьютера: `./deploy/deploy.sh IP_СЕРВЕРА` (нужен SSH-доступ пользователем deploy, его создаёт `deploy/setup-server.sh`).

## Перед публикацией игр в RuStore

- Проверьте политику конфиденциальности (`src/privacy.html` и `src/en/privacy.html`) с юристом и добавьте реквизиты оператора (ИП или ООО) после регистрации. Перед выходом каждой игры добавьте в политику её раздел, как у «Вотчины»: перечень сервисов (реклама, аналитика) должен совпадать с тем, что реально встроено в игру.
- В консоли RuStore укажите ссылки: политика — https://gornitsa.games/privacy.html (для «Вотчины» можно сразу на её раздел: https://gornitsa.games/privacy.html#votchina), поддержка — https://gornitsa.games/support.html.
- Карточки игр — в `src/index.html` и `src/en/index.html`, раздел «Наши игры». У «Анамнеза» пока нет снимков экрана: когда появятся, положите баннер 1024×500 в `site/assets/games/` и замените заглушку `game-shot-soon` картинкой, как у «Вотчины», «Длинных нард» и «Сказов». «Узоры» — в строке «В планах».

## Страницы «Длинных нард»

`src/nardy/index.html` и `src/en/nardy/index.html` — https://gornitsa.games/nardy/. Тексты — из папки `store/` репозитория Nefeste/nardy (карточка RuStore, вопросы и ответы); картинки `site/assets/games/nardy-*` — оттуда же: иконка, баннер и снимки рисуются кодом (`tools/store/shots.ts` в nardy) и переводятся в WebP (снимки — 960×540). Поменялась карточка или снимки в nardy — перенесите сюда.

- Когда в RuStore откроется предзаказ — раскомментируйте кнопку в `src/nardy/index.html` (адрес `https://www.rustore.ru/catalog/app/games.gornitsa.nardy`) и добавьте ссылку «RuStore» в карточку на главной.
- Политика: у нард пока ссылка на раздел «Игры в разработке». Перед выходом игры — свой раздел, как у «Вотчины»; черновик — `store/privacy.ru.md` в nardy.

## Страницы «Сказов»

папки `store/` репозитория Nefeste/skazy (карточка RuStore, частые вопросы); картинки

## Сервер игры «Вотчина»

Cloudflare у части российских провайдеров работает с перебоями, поэтому онлайн «Вотчины» переезжает на эту же машину: https://votchina.gornitsa.games (решение — ADR 0019 и спецификация `docs/specs/2026-09-server-ru.md` в репозитории Nefeste/votchina). Код сервера — тот же воркер, запущенный под Node; база — файл SQLite `/var/lib/votchina/votchina.db`.

Как устроено на машине (всё ставит `deploy/votchina/setup.sh`, его запускает автообновление сайта):

- служба `votchina` — `node serve.mjs` на 127.0.0.1:8787 от пользователя `votchina`; nginx отдаёт её наружу по HTTPS;
- `votchina-pull` каждые 2 минуты: забирает из закрытого репозитория ветку `vps` (сборку, прошедшую сквозной тест в CI) ключом только для чтения `/etc/votchina/deploy_key`; новая сборка — перезапуск, не ответила — возвращается прежняя. Ветка `vps-import` — выгрузка базы D1 при переезде, зашифрованная ключом машины (`/etc/votchina/age.key`);
- сертификат Let's Encrypt выпускается сам, как только A-запись `votchina` указывает на сервер;
- копия базы — раз в сутки в `/var/backups/votchina/`, хранится семь дней; журнал запросов nginx — три дня;
- открытые ключи машины: https://votchina.gornitsa.games/.well-known/votchina-deploy.pub (его добавляют в Nefeste/votchina → Settings → Deploy keys, без права записи) и `votchina-age.pub` (им задание переезда шифрует выгрузку).

Настройки службы — `/etc/votchina/env` (там же секрет `ADMIN_TOKEN` для `server/tools/delete-by-tag.sh`). Журналы: `journalctl -u votchina -u votchina-pull -n 50`.

Переезд выполнен 27 сентября 2026 года заданием «Переезд на свой сервер» в репозитории votchina: база на этой машине, старый адрес на Cloudflare пересылает API. Осталось выпустить версию приложения 2.10.2 с новым адресом; копию базы в Cloudflare D1 удалить, когда старых версий не останется.

## Сервер игры «Длинные нарды»

Онлайн нард — стол с другом и честные кубики — работает на этой же машине: https://nardy.gornitsa.games (решение — ADR 0018 и спецификация `docs/specs/2026-09-server-vps.md` в репозитории Nefeste/nardy). Сервер — один процесс Bun с базой SQLite `/var/lib/nardy/nardy.db`; устроен так же, как «Вотчина», только среда — Bun, а в nginx пропускается WebSocket.

Как устроено на машине (всё ставит `deploy/nardy/setup.sh`, его запускает автообновление сайта при каждом изменении `deploy/nardy/`):

- Bun — официальная сборка с GitHub, версия закреплена в `setup.sh` (та же, что в CI нард) и сверяется по SHA-256; лежит в `/opt/bun/<версия>/bun`;
- служба `nardy` — `bun server.js` на 127.0.0.1:8790 от пользователя `nardy`, память — не больше 300 МБ; nginx отдаёт её наружу по HTTPS, `/v1/live` — WebSocket;
- `nardy-pull` каждые 2 минуты: забирает из закрытого репозитория ветку `vps` (сборку, прошедшую тесты сервера в CI) ключом только для чтения `/etc/nardy/deploy_key`; новая сборка — перезапуск, не ответила на `/v1/ping` — возвращается прежняя;
- сертификат Let's Encrypt выпускается сам, как только A-запись `nardy` указывает на сервер;
- копия базы — раз в сутки в `/var/backups/nardy/`, хранится семь дней; журнал запросов nginx — три дня.

Настройки службы — `/etc/nardy/env` (там же секрет `ADMIN_TOKEN` для удаления профиля по просьбе). Журналы: `journalctl -u nardy -u nardy-pull -n 50`.

Чтобы сервер поднялся, владельцу нужно два шага:

1. У регистратора — A-запись `nardy` на тот же адрес, что у `gornitsa.games`.
2. Ключ машины — в Nefeste/nardy → Settings → Deploy keys, **без** права записи. Сам ключ: https://nardy.gornitsa.games/.well-known/nardy-deploy.pub (открывается после A-записи) или в журнале `journalctl -u gornitsa-update -n 80`.

Сборка появляется в ветке `vps` после первого слияния сервера в main нард. Проверка: `curl https://nardy.gornitsa.games/v1/ping`.
